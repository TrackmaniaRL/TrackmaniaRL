# Isolated recovery

`python -m tools.headless_campaign_queue.recovery --config ABS_CONFIG --config-sha256 SHA --checkpoint ABS_CHECKPOINT --destination ABS_FRESH_DIRECTORY` prepares an isolated FULL-state copy; it does not start an environment. It requires Linux root, no live competing training/native processes, the global campaign lock, the latest durably logged checkpoint, matching fingerprint and no unacknowledged actor spool. It copies the SQLite database plus its WAL without opening the originals, checks the copy's identity, frontier and receipt hashes, and proves restore/replay in a separate temporary copy. Source checkpoint, config, database and WAL are checked again and never intentionally modified.

The default stage `training` requires an incomplete budget and a recovered WAL below the target. Add `--stage evaluation --max-overshoot N` to prepare a new independent 30-trial suite from an already complete, drained checkpoint. Existing partial evaluations are preserved. `--execute` starts the selected operation in the isolated copy. Resume uses `trackmaniarl resume` with FULL state, never `--reset-replay`. Tracking is offline. A disk guard requests a cooperative stop if reserves are violated. Process identity and status are recorded in `recovery.json`.

Status `training_exited_unverified` is not a completed training or evaluation; `evaluation_verified_queue_pending` is not a completed campaign. Both return code 3 because this module does not yet link a recovery receipt into the existing queue or continue later jobs. A failed/interrupted run, live or ambiguous ownership, changed fingerprint, pending actor spool, invalid checkpoint, budget exceeded by WAL replay, unverified drain, or stale global lock fails closed. Hard-kill, native descendants that detach from the process group, and a stop file that cannot be written still require inspection. Never remove an existing lock until exact process identities are confirmed gone. A different model/config/source fingerprint cannot be forced through this recovery. Data not yet durably accepted when a process died may have been lost; this cannot be inferred from the checkpoint.
